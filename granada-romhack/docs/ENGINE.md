# Granada (Mega Drive, Wolf Team 1990) — карта движка

Всё ниже получено реверс-инжинирингом ROM `GRANADA` / `GM T-32023 -00`
(512 КБ, регион JU). Каждый адрес подтверждён либо дизассемблированием,
либо чтением живой RAM из запущенного эмулятора. Публичного
дизассемблирования Granada не существует — это результат анализа с нуля.

## Общая структура

| Диапазон | Содержимое |
|---|---|
| `000000–0001FF` | таблица векторов + заголовок |
| `000200–018D70` | код 68000 |
| `018D70–06C97C` | графика, карты, объекты, музыка |
| `06C97C–06E700` | **свободно** (залито `FF`) — сюда внедряется код хака |
| `06E700–080000` | данные демо-записей и прочее |

## Загрузочная проверка контрольной суммы

```
000300  tst.w   $C00004          ; VDP
00031C  lea     $1A4.w,a0        ; конец ROM из заголовка
000334  add.w   (a0)+,d1         ; сумма слов 0x200..конец
00033E  lea     $18E.w,a0
000342  cmp.w   (a0),d1
000344  bne     $3D6             ; -> красный экран и вечный цикл
```

**Любой патч обязан пересчитать слово по `0x18E`**, иначе игра не
загрузится. `tools/granada.py:fix_checksum()` это делает.

## Главный конечный автомат

```
00039E  move.b  #0,$FFF600       ; номер режима
0003A4  move.b  $FFF600,d0
0003A8  andi.w  #$1F,d0
0003AC  jsr     $3B2(pc,d0.w)    ; таблица по 6 байт на запись
```

| `$FFF600` | обработчик | что это |
|---|---|---|
| `00` | `$22FC` | загрузочная заставка |
| `06` | `$2EB4` | титульный экран / опции |
| `0C` | `$4658` | демо-режим (две записи: `$6EF00`, `$6E700`) |
| `12`/`18`/`1E` | `$4696` | игровой процесс |

## Таблицы стадий

`$FFABE1` — **номер стадии, 0..8** (9 стадий). Им индексируются шесть рядов
длинных указателей, по 9 записей (`0x24` байта) в ряду:

| Адрес | Назначение | Куда кладётся |
|---|---|---|
| `0x60BE` | блок-карта 64×64 байта (`0x1000`) | `$FFAB08` |
| `0x60E2` | определения блоков, 256 × 16 байт | `$FFAB0C` |
| `0x6106` | сжатый тайлсет стадии | — (распаковка в VRAM) |
| `0x612A` | палитра, 32 байта | `$FFB30E` |
| `0x614E` | таблица атрибутов тайлов, байт на тайл | `$FFAB10` |
| `0x6172` | **список спавна объектов** | — |

Дополнительно: `0x4646` — ID музыки (слово на стадию), `0x2B254` — стартовая
позиция игрока (16 байт на стадию, два длинных слова, сдвигаются `<<8`),
`0x6310` / `0x6392` / `0x63A4` — прочие параметры стадии.

## Формат карты

Классическая трёхуровневая метатайловая схема. Код выборки — `$895E`:

```
00895E  movem.l d6-d7/a0,-(a7)
008966  move.b  d0,d7 ; lsr.b #2,d7     ; d0 = X в тайлах (БАЙТ)
00896A  move.b  d1,d6 ; lsr.w #2,d6 ; lsl.w #6,d6
008970  add.w   d6,d7
008972  andi.w  #$FFF,d7              ; 64*64 = 4096 блоков
008976  add.l   $FFAB08,d7            ; блок-карта
008980  move.b  (a0),d6 ; lsl.w #4,d6 ; +4*(y&3) + (x&3)
008996  add.l   $FFAB0C,d6            ; определения блоков
0089A2  add.l   $FFAB10,d0            ; таблица атрибутов
0089AA  move.b  (a0),d0               ; -> атрибут
```

То есть: **64×64 блока, блок = 4×4 тайла → мир 256×256 тайлов (2048×2048 px)**.
Мировые координаты в записях спавна — 0..0x7FF, тайл = `координата >> 3`.

Биты атрибута, которые движок выделяет при построении своего буфера
столкновений в `$FF0000` (код `$5FE4`–`$6060`), — маска `0x50`.

### Почему карту нельзя сделать больше 256×256 тайлов

1. `move.b d0,d7` / `move.b d1,d6` в `$8966`–`$896A` — координаты тайлов
   **однобайтовые**, мир замыкается на 256 тайлах.
2. `andi.w #$FFF` жёстко задаёт 4096 блоков.
3. Буфер столкновений в `$FF0000` занимает `0x4000` байт, а область
   `$FF4000–$FF7FFF` тоже занята (проверено прогоном на эмуляторе:
   9590 байт там изменяются во время игры). Свободных 16 КБ в 64 КБ
   рабочей памяти для буфера большего размера **нет**.

Расширение потребовало бы переписать координатную систему во всех
вызывающих местах (`$88B0`, `$7C7E`, `$8826`, `$8906`, камера, скроллинг)
и найти новую память — это переделка движка, а не патч.

## Объекты стадии

Список спавна (`0x6172`) — **ровно 128 записей по 8 байт**:

```
+0  word  тип объекта (0 = слот пуст)
+2  word  X
+4  word  Y
+6  word  параметр
```

Загрузчик `$5B60`–`$5D3A` раскладывает их в массив `$FF8000`, шаг `0x20`:

```
005B7C  moveq   #$7F,d7               ; 128 слотов
005B80  move.w  (a0),d0 ; beq $5D2E   ; тип 0 -> пропустить слот
005B88  lsl.w   #5,d0 ; addi.l #$2A150,d0   ; шаблон объекта
005BD6  tst.w   $14(a2) ; beq ...
005BDE  addq.w  #1,$FFB434            ; счётчик целей стадии
005D2E  addq.l  #8,a0 ; adda.l #$20,a1 ; dbra d7,$5B7E
```

### Шаблоны объектов — `0x2A150`, по 32 байта на тип

| Смещение | Значение |
|---|---|
| `+00` | ID спрайта |
| `+02` | размер / радиус |
| `+04` | **очки прочности (HP)** |
| `+06` | очки за уничтожение |
| `+0C` | ID поведения (AI) |
| `+12` | форма коллизии |
| `+14` | **≠0 — объект считается целью стадии** |

Боссы (одна штука на стадию, `+14` ≠ 0, высокая цена):

| Стадия | Тип | HP | Очки |
|---|---|---|---|
| 1 | `0x25` | `0x40` | 10000 |
| 2 | `0x11` | `0x40` | 512 |
| 3 | `0x1E` | `0x20` | 512 |
| 4 | `0x26` | `0x20` | 230 |
| 5 | `0x43` | `0x40` | 10000 |
| 6 | `0x1B` | `0x40` | 512 |
| 7 | `0x08` | `0x60` | 556 |
| 8 | `0x24` | `0x80` | 10000 |
| 9 | `0x12` | `0x100` | 10000 (финальный) |

У типа есть обработчик инициализации (таблица `0x5D3C`, длинное слово на тип).
Для босса 1-й стадии это `$5C70` — он просто заливает 4608 байт графики
из `0x2E174` в VRAM, поэтому **два экземпляра босса безопасны**: второй
записывает те же данные по тому же адресу.

## Завершение стадии и переход

```
004BD2  tst.w   $FFB434 ; ble $4BDC    ; все цели уничтожены?
004BE4  cmpi.w  #$FFFE,$FFB434         ; отсчёт после зачистки
004C00  cmpi.w  #$FFB0,$FFB434 ; bge $4BA6
004C10  addq.b  #1,$FFABE1             ; следующая стадия
004C20  cmpi.b  #8,$FFABE1
004C28  ble     $4C36                  ; -> bra $4846 (инициализация стадии)
004C2C  move.w  #0,$FFFE02             ; игра пройдена ->
004C32  bra     $434                   ;    возврат к заставке
```

`$4C2C` — точка врезки New Game+.

## Управление

```
002050  move.b  #$00,$A10003 ; nop;nop ; move.b $A10003,$FFF604
002064  move.b  #$40,$A10003 ; nop;nop ; move.b $A10003,$FFF602
```

* `$FFF602` (TH=1): бит 0 Вверх, 1 Вниз, 2 Влево, 3 Вправо, 4 **B**, 5 **C**
* `$FFF604` (TH=0): бит 4 **A**, 5 **Start** (активный уровень — низкий)

Назначение кнопок настраиваемое: `$FFBF18` (A), `$FFBF1A` (B), `$FFBF1C` (C),
`$FFBF1E` (A+B), `$FFBF20` (B+C) хранят смещение в массив действий `$FFBF22`.
По умолчанию (`$3BA8`, `$2F30`) комбинации A+B и B+C **не назначены**, а A+C
движок не читает вообще — эти три комбинации свободны.

Действия: `$FFBF23` — огонь, `$FFBF24`/`$FFBF29` — фиксация башни,
`$FFBF26` — ускорение.

## Снаряды

```
$9830(kind, X, Y, vx, vy, angle, p6, p7)   ; 8 длинных слов на стеке
```

Берёт слот из свободного списка `$FFABCC` (счётчик `$FFAB3C`), пишет 8 полей.
Поведение снаряда выбирается таблицей `0x9FC0` по полю `+0`, **видов 1..6**;
штатная пушка игрока стреляет видом 1 (`$97EC`–`$9820`), вид 2 звучит иначе.

Направление берётся из двух таблиц по 64 длинных слова:
`0x8EC6` и `0x8FC6` (индекс = угол × 4, углов 64).

## Свободная рабочая память

Проверено прогоном оригинала: `$FFF650–$FFF6FF`, `$FFD000–$FFD0FF`,
`$FF9000–$FF90FF` не трогаются движком. Хак использует `$FFF650+`.
