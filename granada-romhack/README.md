# Granada NG+ — ромхак для Sega Mega Drive

Хак игры **Granada** (Wolf Team, 1990). Движок разобран с нуля —
публичного дизассемблирования, редактора уровней или документации формата
данных для этой игры не существует, всё в `docs/ENGINE.md` получено
реверс-инжинирингом и проверено на живой RAM в эмуляторе.

Исходный ROM в репозиторий не входит. Патч применяется к вашей копии.

| Функция | Статус |
|---|---|
| **New Game+** с нарастающей сложностью | готово, проверено на эмуляторе |

| **Два босса на 1-м уровне** вместо одного | готово, проверено |
| **Изменённые карты**, расширенная игровая зона | готово, проверено |
| **Новое оружие на X / Y / Z** | готово; см. оговорку про геймпад ниже |
| **SPECIALS в опциях** — раскладка оружия | готово, проверено |
| **Агрессивнее мобы** | готово |

### New Game+

После зачистки 9-й стадии игра не возвращается на заставку, а начинает
новый круг: стадия 1, счёт, жизни и прогресс сохраняются, счётчик петли
`NG+` увеличивается. **Прочность всех врагов и боссов умножается на
`NG+ + 1`** — на NG+1 вдвое, на NG+2 втрое и так до ×8.

Реализовано врезкой в `$4C2C` (ветка «игра пройдена») и в `$5BCC`
(копирование HP из шаблона объекта при спавне).

### GAME MODE в меню опций

В экран опций добавлена строка **GAME MODE** со значениями
`NORMAL`, `NG+1` … `NG+7` — можно начать игру сразу на любом круге,
не проходя её целиком. Переключается влево/вправо, как RANK.

```
  GRANADA      3
  RANK         EASY
  MUSIC        00
  S.E          00
  REVERSE      QUICK
  KEY ASSIGN
  GAME MODE    NORMAL      <-- новая строка
  EXIT
```

Выбранный режим применяется при старте игры (и из GAME START, и из
CONTINUE) и дальше растёт сам при зацикливании. Настройка живёт в
`$FFFE1E` — первом свободном слове за штатным блоком опций, поэтому
переживает мягкий сброс вместе с остальными настройками.

Под это пришлось: расширить курсор меню с 7 строк до 8, перенести
таблицу обработчиков строк (`0x3B84`, 7 записей, расширить на месте было
некуда) в свободную область ROM и сдвинуть EXIT на строку вниз.
Автотесты отдельно проверяют, что штатные строки меню после переноса
таблицы продолжают работать.

### Два босса на 1-м уровне

В список спавна 1-й стадии добавлена вторая копия босса (тип `0x25`,
HP `0x40`) в свободный слот на проходимой земле в 32 тайлах от первого.
Счётчик целей стадии вырос с 18 до 19 — уровень не засчитывается, пока
не уничтожены оба. Площадка вокруг пары расчищена, чтобы бой был
осмысленным.

Это безопасно потому, что обработчик инициализации босса (`$5C70`) только
заливает его графику в VRAM: второй экземпляр пишет те же байты по тому же
адресу.

### Карты

Карты стадий изменены: найдены и подключены большие открытые участки,
до которых в оригинале **невозможно было добраться** от точки старта.
Доля мира 256×256 тайлов, реально достижимая игроком:

| Стадия | Было | Стало |
|---|---|---|
| 1 | 50.2 % | 50.6 % (плюс расчищенная арена боссов) |
| 3 | 54.2 % | **67.4 %** |
| 4 | 53.5 % | **91.9 %** |
| 5 | 49.2 % | **63.0 %** |
| 6 | 35.3 % | 35.6 % |
| 7 | 56.7 % | **70.4 %** |
| 8 | 67.8 % | **93.9 %** |

Коридоры прорубаются по кратчайшему пути и только через клетки, которые
сейчас сплошные; существующая застройка не трогается, а покрытие берётся
из блока, уже встречающегося на этой же стадии, — поэтому новая земля
выглядит родной.

**Честная оговорка про «увеличить размеры».** Сам мир стадии физически
нельзя сделать больше 256×256 тайлов: координаты тайлов в движке
однобайтовые (`move.b d0,d7` в `$8966`), индекс блок-карты обрезан
`andi.w #$FFF`, а свободных 16 КБ рабочей памяти под буфер столкновений
большего размера в приставке нет — область `$FF4000–$FF7FFF` занята
(проверено замером на эмуляторе). Поэтому увеличена **игровая площадь
внутри** существующего мира, а не его габариты. Подробности и точные
инструкции, которые это ограничивают, — в `docs/ENGINE.md`.

### Новое оружие

Три орудия поверх штатной пушки (A), каждое со своей перезарядкой:

| Кнопка | Оружие | Что делает | Перезарядка |
|---|---|---|---|
| **X** | **Hyper Beam** | 8 снарядов выкладываются в линию вдоль прицела с шагом 12 px — читается как один луч, а не очередь | 55 кадров |
| **Y** | **Support Fire** | включает на 5 секунд сопровождение: два фланговых ствола сами находят ближайшую живую цель и бьют по ней каждые 14 кадров, пока заряд не кончится | 420 кадров |
| **Z** | **Nova** | замкнутое кольцо из 8 снарядов через 45° | 34 кадра |

Support Fire наводится движковым арктангенсом `$8456` по ближайшему живому
объекту из массива `$FF8000` — то есть это не «ещё один веер», а настоящее
автонаведение, работающее после отпускания кнопки.

### Раскладка: SPECIALS

Orудия по умолчанию висят на **X / Y / Z** — для них нужен 6-кнопочный
геймпад (в эмуляторе переключите контроллер в режим 6 кнопок).

Если такого пада нет, в опциях есть строка **SPECIALS**:

| Значение | Раскладка |
|---|---|
| `X Y Z` (по умолчанию) | X / Y / Z на 6-кнопочном паде |
| `COMBO` | **A+B** — Hyper Beam, **A+C** — Support Fire, **B+C** — Nova |

Режим `COMBO` сделан отключаемым намеренно: A, B и C в этой игре заняты
(огонь, фиксация башни, ускорение), и комбинации неизбежно срабатывают
во время обычной стрельбы. Поэтому он не включён по умолчанию.

> **Оговорка про 6 кнопок.** Встроенный в проверку эмулятор (Genesis Plus GX
> и picodrive через stable-retro) умеет только 3-кнопочный пад и не даёт его
> переключить. Поэтому автотестами проверена вся логика орудий — но через
> режим `COMBO`. Сам шестикнопочный обмен написан по стандартному протоколу
> (три лишних переключения TH, опознание пада по нулевому младшему ниблу,
> не чаще раза в кадр), однако выполнить его в этом окружении не на чем.
> Если на реальном 6-кнопочном паде X/Y/Z не сработают — включите `COMBO`.

### Агрессивнее мобы

У каждого типа объекта в шаблоне есть поле `+6` — радиус активации: пока
игрок дальше, ИИ этого объекта не выполняется вообще. Радиус поднят
**на 25 % у 82 типов**, так что противники вступают в бой раньше и с
большей дистанции. Боссы (`0x2710` — всегда активны) не затронуты.

Коэффициент меняется при сборке:

```bash
GRANADA_AGGRO=3,2 python3 tools/build.py <rom> -o out.gen   # x1.5
```

Честно: насколько именно это меняет сложность, я померить не смог —
одиночные прогоны в этой игре слишком шумные (результат «сколько секунд
проживёшь, стоя на месте» скачет от 2 до 25 секунд при одном и том же
билде). Поэтому заявляю только структурное изменение радиуса, а не
конкретный прирост сложности.

## Сборка

```bash
pip install capstone stable-retro pillow
```

```bash
python3 tools/build.py "Granada (Japan, USA) (En).gen" -o granada_ngplus.gen
```

Получите пропатченный ROM и `granada_ngplus.ips` рядом. Готовый патч
`granada_ngplus.ips` также лежит в корне репозитория — его можно наложить
на оригинальный ROM любым IPS-патчером (`Lunar IPS`, `Flips`, `ips.py`).
Сборка детерминирована, собранный патч совпадает байт в байт с готовым.

Контрольная сумма
в заголовке пересчитывается автоматически — без этого игра не загрузится
(проверка в `$31C`–`$344`).

Посмотреть внедрённый код 68000 с дизассемблированием:

```bash
python3 tools/build.py <rom> -o out.gen --listing
```

## Проверка

```bash
python3 tools/build.py <rom> -o /tmp/hack.gen
python3 tools/build.py <rom> --test-autoclear -o /tmp/auto.gen
python3 tools/testbench.py /tmp/hack.gen /tmp/auto.gen
```

Прогоняет настоящий эмулятор без экрана (26 проверок): загрузка ROM, вход
в игру, наличие двух боссов, счётчик целей, работа каждого орудия, меню
опций — новая строка, её пределы, применение режима при старте и
работоспособность штатных строк, полный круг из 9 стадий и переход в NG+
дважды, рост HP боссов 64 → 128 → 192.

`--test-autoclear` — только для тестов: отключает регистрацию целей, из-за
чего стадии зачищаются сами примерно за 80 кадров, что позволяет пройти
весь цикл NG+ автоматически.

## Работа с картами

```bash
python3 tools/map_tool.py info   <rom>                 # все стадии: слои, старт, % достижимого
python3 tools/map_tool.py render <rom> <0-8> map.png   # картинка карты
python3 tools/map_tool.py export <rom> <0-8> map.bin   # блок-карта 64x64 = 4096 байт
python3 tools/map_tool.py import <rom> <0-8> map.bin out.gen
```

На картинке: тёмное — сплошное, зелёное — проходимое и достижимое,
коричневое — открытое, но отрезанное от старта, жёлтое — старт игрока,
красное — боссы, синее — прочие объекты.

## Состав

```
tools/granada.py    карта движка: все найденные адреса и структуры
tools/asm68k.py     мини-ассемблер 68000 под нужные формы команд
tools/build.py      сборщик хака: патчи, карты, контрольная сумма, IPS
tools/map_tool.py   просмотр, экспорт и импорт карт стадий
tools/testbench.py  автотесты на эмуляторе
tools/emu.py        обвязка Genesis Plus GX (headless)
docs/ENGINE.md      результаты реверс-инжиниринга движка
docs/*.png          отрисовки карт (1-я стадия, 4-я до/после)
granada_ngplus.ips  готовый патч
```

Весь внедряемый код занимает около 1.6 КБ в свободной области `0x6C980`
(в оригинале залита `FF`). Всего от оригинала отличается 911 байт — 0.17 %.
